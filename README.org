* How components look like?

While the resulting UI and style is mostly left to the developers, /hygguile/ has some opinionated choices. The biggest goal of the project is to provide an expressive DSL for defining user interfaces that look professional and cozy.

We try to use names which are same or similar to the HTML spec for our components, so as to ease the cognitive load of having to learn "yet another library".

You can always choose to import hygguile using a prefix to avoid name clashes if they happen.

#+begin_src scheme
(use-modules
  ((hygguile) #:prefix hyg:)
#+end_src


I'd encourage navigating to the ~src/hygguile~ directory and studying the code to see what possibilities and reusable components are there.

#+begin_src scheme
(input #:label (G_ "User name")
           #:name "username"
           #:value ""
           #:required #t)

;; some pre-defined helpers exist
(submit-button "click here")

;; or if you want more control, you can go more low-level
(button "click here"
            #:type 'submit
            #:background 'bg-green-700
            #:hover-background 'hover:bg-green-900
            #:border-color 'border-green-900)

#+end_src

One of the main abstractions we use is the ~mk-class~ procedure, which takes a list of symbols and converts it into an ordered set of classes and consequently to an HTML compatible class list. We have adopted Tailwind's syntax since it's clear and concise, and well documented.

Thanks to the ~mk-class~ abstraction we could at some point even change the underlying implementation to use something different than Tailwind CSS by converting class names. This gives us an effective sort of dependency injection in CSS, making us a bit more independent of CSS library hygguile is built on.

With it you can get neat HTML output:

#+begin_src scheme
(define my-component
  `((p (@(class ,(mk-class '(my-2 p-2 bg-stone-200))) "Some paragraph")))

;; this gives you
;; <p class="bg-stone-200 my-2 p-2">Some paragraph</p>  
#+end_src

* Installing and Using

See the [[file:Makefile][Makefile]] for more details and common tasks.

You should take the files at ~resources~ and load them into your web app, in the way you like. This means loading CSS, JS and TTF files.

You can take a look at the ~showcase.scm~ file which includes some facilities and advanced techniques to load these things.

To install it you can download the source code files and add them to your ~GUILE_LOAD_PATH~ or even better, use a Guix shell ~manifest.scm~ and add the package with something like this:

#+begin_src scheme
(define-public guile-hygguile
  (package
    (name "guile-hygguile")
    (version "0.2.2")
    (source
     (origin
       (method git-fetch)
       (uri (git-reference
             (url "https://codeberg.org/jjba23/hygguile.git")
             (commit (string-append "v" version))))
       (file-name (git-file-name name version))
       (sha256
        (base32 "0gcd5l5k39m0q3l4z7kndc06m6s8nrkpybflc0h70bjkabgm38rl"))))
    (build-system guile-build-system)
    (native-inputs (list guile-3.0))
    (arguments
     (list
      #:source-directory "src"))
    (home-page "https://codeberg.org/jjba23/hygguile")
    (synopsis
     "SXML and TailwindCSS UI component library for Lisp (Guile Scheme) software projects")
    (description
     "Cozy and professional user-interfaces for everyone.
        SXML and TailwindCSS UI component library for Lisp (Guile Scheme) software projects.
        hygge + guile = hygguile")
    (license license:lgpl3+)))
#+end_src
